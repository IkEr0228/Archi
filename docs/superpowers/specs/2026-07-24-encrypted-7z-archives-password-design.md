# Encrypted 7z Archives with Password Support — Design Specification

**Дата:** 2026-07-24  
**Тема:** Полная поддержка паролей (AES256) для создания, открытия и распаковки 7z-архивов  
**Текущий статус:** Дизайн утверждён пользователем

## 1. Обзор фичи
- Полная поддержка паролей (AES256) только в backend (vendor sevenz-rust2).
- Frontend: Точный UX как просил пользователь — **отдельное окно** в том же стиле интерфейса Archi для ввода пароля.
- Создание, открытие и распаковка.
- Опция «Запомнить на сессию».
- Не трогаем существующий unencrypted путь — он остаётся по умолчанию.

## 2. Основной дизайн окна пароля
### Компонент `PasswordDialog.svelte` (переиспользуемый)
- Точное соответствие стилю Archi (тёмная тема, шрифты, иконки, анимации, rounded corners, shadows).
- Для **создания**:
  - Заголовок «Пароль для нового архива»
  - Поле ввода пароля
  - Чекбокс «Запомнить на сессию»
  - Кнопки «Отмена» / «Создать архив»
- Для **открытия / распаковки**:
  - Заголовок «Пароль для архива: имя_архива.7z»
  - Поле ввода
  - Чекбокс «Запомнить на сессию»
  - Кнопки «Отмена» / «Распаковать» / «Открыть в архиваторе»

### Триггеры
- Создание: из `CreateArchiveModal.svelte` перед открытием диалога.
- Открытие/распаковка: отдельное окно **перед** любым действием распаковки (не в модале открытия).

## 3. Технологическая архитектура
### Tauri команды (добавить в `src-tauri/src/commands.rs` и `lib.rs`)
- `create_archive(password: Option<String>) -> Result<...>`
- `open_archive(path: String, password: Option<String>)`
- `extract_archive(path: String, password: Option<String>)`

### Backend (sevenz-rust2)
- `Password::new(password)` или пустой пароль для unencrypted.
- AES256-SHA256 как в существующем vendor.

### Frontend
- Новый/переиспользуемый компонент `PasswordDialog.svelte`.
- Обработка ввода → отправка команды Tauri.
- Сессионное запоминание (localStorage или Tauri state).

## 4. UX и flow
- Отдельное окно в едином стиле всего приложения.
- Автофокус на поле пароля.
- После успешного ввода — сразу действие (создать/распаковать).
- Обработка ошибок: неправильный пароль → сообщение + повторный ввод.

## 5. Security & Best Practices
- Пароли никогда не хранятся в открытом виде.
- AES256 на уровне 7z.
- Для open/extract — диалог только один раз перед началом операции.
- Поддержка «remember on this session» для удобства.
